# REQ-001 공개 포트폴리오

## 1. 목적

`greengroove.app`을 면접 및 이직 과정에서 공개할 수 있는 개발자 포트폴리오로 구축한다.

방문자가 짧은 시간 안에 다음 내용을 파악할 수 있어야 한다.

* 개발자의 이름, 정보, 경력
* 주로 사용하는 기술 스택
* 만든 프로젝트
* 참여한 프로젝트
* 프로젝트 상태 (프로젝트가 실제 사용 중인지 단순 개발 결과물인지)

## 2. 주요 사용자

### 면접관 및 개발 조직

프로젝트의 목적, 기술 구성, 개발자의 담당 범위와 현재 상태를 확인한다.

### 채용 담당자

개발자의 경력, 기술 스택, 대표 프로젝트와 외부 링크를 빠르게 확인한다.

### 개발자 본인

완성된 사이드 프로젝트를 포트폴리오에 등록하고 공개한다.

## 3. 공개 화면

### 3.1 홈 화면

홈 화면에는 다음 정보를 표시한다.

* 이름
* 경력 요약
* 간단한 개발자 소개
* 주요 기술 스택
* 대표 프로젝트
* GitHub 링크
* 이력서 링크
* 연락처

#### 경력 표현 예시

```text
Java와 Spring Boot 기반의 백엔드 웹개발자
업무 시스템 개발 및 운영 경험
```

#### 개발자 소개 예시

```text
백엔드 웹개발자입니다.
```

### 3.2 프로젝트 목록 화면

공개된 프로젝트를 목록으로 표시한다.

각 프로젝트에는 다음 정보를 표시한다.

* 프로젝트명
* 한 줄 설명
* 주요 기술
* 현재 상태
* 프로젝트 상세 링크
* GitHub 링크
* 배포 링크

프로젝트 진행률을 숫자나 퍼센트로 표시하지 않는다.

### 3.3 프로젝트 상세 화면

프로젝트 상세 화면에는 다음 정보를 표시한다.

#### 기본 정보

* 프로젝트명
* 한 줄 설명
* 개발 기간
* 현재 상태

#### 프로젝트 설명

* 주요 기능
* 어떤 문제를 해결하려 했는가

#### 기술 정보

* Backend
* Frontend
* Database
* Infrastructure
* Testing

#### 개발자 역할

* 요구사항 정의
* 데이터 모델 설계
* API 설계
* 백엔드 구현
* 프론트엔드 구현
* 테스트
* 배포

실제로 담당하지 않은 작업은 표시하지 않는다.

#### 프로젝트 운영 상태

프로젝트가 실제 사용 중인지 개발 결과물인지 명확하게 구분한다.

상태는 다음 값을 사용한다.

| 상태           | 설명          |
| ------------ | ----------- |
| `DEVELOPING` | 현재 개발 중     |
| `DEPLOYED`   | 배포 후 검증 중   |
| `IN_USE`     | 실제 사용 중     |
| `COMPLETED`  | 목표 기능 구현 완료 |
| `ARCHIVED`   | 개발 종료 또는 보관 |

화면에는 한국어로 표시한다.

## 4. 최초 공개 프로젝트

최초 공개 프로젝트는 `greengroove.app` 자체로 한다.

### 프로젝트명

```text
GreenGroove
```

### 프로젝트 설명

```text
개발자의 경력, 기술과 프로젝트를 면접관에게 효과적으로 소개하기 위한 공개 포트폴리오
```

`GreenGroove` 프로젝트 상세 화면에는 다음 내용을 포함한다.

* 포트폴리오를 만들게 된 배경
* 주요 공개 정보
* 사용 기술
* 요구사항 문서와 GitHub Issue 기반 개발 방식
* 현재 배포 및 사용 상태

## 5. 공개 정보

다음 정보는 공개할 수 있다.

* 이름
* 경력 요약
* 공개 가능한 기술 경험
* 개인 사이드 프로젝트
* 프로젝트 기술 스택
* GitHub 공개 저장소
* 프로젝트 배포 주소
* 이력서
* 연락용 이메일

## 6. 공개하지 않을 정보

다음 정보는 공개하지 않는다.

* 회사 소스 코드
* 고객사 및 내부 시스템 상세 정보
* 실제 회사 데이터
* API 키와 인증정보
* 서버 접속정보
* 개인 전화번호
* 상세 주소
* 비공개 저장소 내부 코드
* 정리되지 않은 아이디어와 개인 메모
* 구현하지 않은 기능을 완료한 것처럼 표현한 내용

## 7. 반응형 지원

다음 환경에서 주요 콘텐츠를 확인할 수 있어야 한다.

* 데스크톱
* 태블릿
* 모바일

모바일에서도 프로젝트 목적, 기술과 현재 상태가 누락되지 않아야 한다.

## 8. MVP 포함 범위

* 홈 화면
* 프로젝트 목록 화면
* 프로젝트 상세 화면
* 개발자 이름과 경력 소개
* 기술 스택 표시
* 대표 프로젝트 표시
* 프로젝트 운영 상태 표시
* GitHub 링크
* 이력서 링크
* 연락용 이메일

* 반응형 화면
## 9. MVP 제외 범위

* 관리자 로그인
* 프로젝트 등록 및 수정 화면
* GitHub API 자동 연동
* 커밋 및 활동 자동 수집
* 블로그
* 방문자 통계
* 검색과 필터
* 프로젝트 진행률 그래프
* 다국어
* 다중 사용자
* 댓글
* 문의 폼
* 실시간 서버 상태 표시

## 10. 완료 조건

* 방문자가 홈 화면에서 개발자의 이름, 경력, 소개와 주요 기술을 확인할 수 있다.
* 방문자가 프로젝트 목록을 확인할 수 있다.
* 방문자가 프로젝트 상세 화면으로 이동할 수 있다.
* 프로젝트 상세에서 제작 목적, 프로젝트 설명, 기술과 운영 상태를 확인할 수 있다.
* 프로젝트가 실제 사용 중인지 개발 결과물인지 구분할 수 있다.
* GitHub, 이력서와 이메일 링크를 사용할 수 있다.
* 데스크톱과 모바일에서 주요 콘텐츠를 정상적으로 확인할 수 있다.
* 공개하면 안 되는 개인정보와 회사 내부 정보가 포함되지 않는다.
